# Social Desk — PWA (v19)

Локальное приложение. Все данные хранятся в браузере (localStorage), наружу ничего не отправляется.

## Состав
- `index.html` — приложение (единый файл)
- `manifest.webmanifest` — манифест PWA
- `sw.js` — service worker (офлайн-режим)
- `icons/` — иконки 180/192/512 + maskable
- `.nojekyll` — отключает обработку Jekyll на GitHub Pages

## Публикация на GitHub Pages
1. Создайте репозиторий, например `social-desk`.
2. Загрузите все файлы этой папки в корень ветки `main`.
3. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
4. Через 1–2 минуты откройте `https://<логин>.github.io/social-desk/`.

## Установка на iPhone
Safari → откройте URL → «Поделиться» → «На экран «Домой»».
Приложение запустится в полноэкранном режиме и работает офлайн.

## Установка на ПК
Chrome/Edge → значок установки в адресной строке.

## Что нового в v13
- **Надёжное хранение:** данные пишутся в IndexedDB и localStorage одновременно. Если браузер очистит localStorage, приложение восстановит данные из IndexedDB при следующем запуске.
- **Закрепление хранилища:** «Данные» → «Закрепить хранилище». В установленном на «Домой» PWA iOS обычно разрешает — тогда данные не удаляются автоматически.
- **Снимки:** хранятся 5 последних состояний (не чаще одного раза в 6 часов). Восстановление — «Данные» → «Восстановить из снимка».
- **Напоминание о резервной копии:** если экспорта не было 7 дней, вверху появится баннер.
- **Календарь:** режимы День / Неделя / Месяц. Выбор сохраняется.
- **Мобильный интерфейс:** нижняя панель навигации, таблицы в виде карточек, полноэкранные формы, ничего не выходит за пределы экрана.

## Обновление с предыдущей версии
Загрузите новый `index.html` и `sw.js` поверх старых. Данные сохранятся — формат состояния не менялся, токен GitHub и настройки остаются в браузере. Кэш service worker помечен новой версией (`social-desk-v18-2`), поэтому обновление подхватится при втором открытии страницы.

## Ограничения
- Работа с реальной папкой на диске (File System Access API) доступна только в Chrome/Edge на десктопе и только по HTTPS. В Safari/iOS используйте экспорт/импорт JSON или ZIP.
- Данные не синхронизируются между устройствами автоматически: переносите файл экспорта JSON. Данные на iPhone и на ПК независимы.
- Ни один браузер не гарантирует вечное хранение. Регулярный экспорт JSON — единственная настоящая страховка. Приложение напомнит.
- Обновление версии: замените `index.html` и увеличьте номер `CACHE` в `sw.js`, иначе браузер отдаст старую копию из кэша.


## Размещение на других бесплатных хостингах

Приложение — статические файлы, поэтому подходит любой статический хостинг с HTTPS. Дорабатывать код не нужно: `start_url` и `scope` заданы относительными (`./`), поэтому приложение работает и в корне домена, и в подпапке.

| Хостинг | Приватный исходник | Свой домен | Как публиковать |
|---|---|---|---|
| GitHub Pages | нет (на бесплатном тарифе) | да | ветка репозитория |
| Cloudflare Pages | да | да | из репозитория или перетаскиванием папки |
| Netlify | да | да | перетаскивание папки в браузере |
| Vercel | да | да | из репозитория |

Все четыре дают HTTPS автоматически — это обязательное условие для service worker и установки на «Домой».

Самый быстрый путь без репозитория: netlify.com/drop — перетащите распакованную папку в окно браузера, получите адрес сразу.

## v14 — вложения и синхронизация

### Вложения
- Файлы (фото до 25 МБ) хранятся как Blob в IndexedDB, в state.json остаётся только ссылка.
- Изображения больше 400 КБ автоматически ужимаются до 2000 px / JPEG 85 %.
- Если IndexedDB недоступен, приложение возвращается к старому base64-режиму.

### Резервная копия ZIP
Данные → «Резервная копия ZIP»: архив `social-desk-backup-YYYY-MM-DD.zip` с `social-desk.json` и папкой `attachments/`.

### Синхронизация с GitHub
1. Создайте **приватный** репозиторий для данных (например `social-desk-data`), отдельный от репозитория сайта.
2. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained token:
   - Repository access: только этот репозиторий
   - Permissions: Contents = Read and write
3. В приложении: Данные → Синхронизация с GitHub → владелец, репозиторий, ветка (`main`), токен → «Сохранить доступ».
4. «Выгрузить в GitHub» — пишет `state.json` и `attachments/<id>` в репозиторий.
5. «Загрузить из GitHub» — заменяет локальные данные копией из репозитория (перед заменой создаётся локальный снимок).
6. «Забыть токен» — удаляет токен и настройки с устройства.

Токен хранится только в localStorage этого браузера и никуда больше не отправляется, кроме api.github.com.
Ограничения GitHub: файл до 100 МБ, рекомендуемый размер репозитория до 1 ГБ.

## v15 — диагностика доступа к GitHub

Кнопка **«✓ Проверить токен»** (Data → GitHub sync) выполняет две проверки и печатает результат:
1. `GET https://api.github.com/user` — токен вообще действителен, показывает имя аккаунта.
2. `GET https://api.github.com/repos/{owner}/{repo}` — репозиторий виден токену, private/public, default branch, есть ли право записи.

Типовые ответы:
- `401 Bad credentials` — токен истёк, отозван или скопирован не полностью.
- `404` — опечатка в owner/repo либо репозиторий не выбран в *Repository access* токена.
- «Нет права записи» — в токене не выдано *Contents: Read and write*.
- «Ветка по умолчанию — master» — исправьте поле «Ветка».

Дополнительно:
- Поля Owner/Repository принимают полный URL (`https://github.com/me/Social-Desk-Data`) и сами его сокращают.
- Из токена удаляются пробелы и переносы строк (частая причина 401 при копировании на iPhone).
- Под полями показывается тип токена, длина и последние 4 символа — так видно, вставилось ли значение целиком (fine-grained ≈ 93 символа).
- Ошибки push/pull теперь текстовые, а не «GitHub 401».

## v16 — навигация, режим чтения, автосинхронизация

- Навигация переехала наверх в виде иконок и стала липкой; нижняя панель убрана.
- Карточки задач и идей открываются в **режиме чтения**: сначала содержимое, правка — по кнопке «✎ Редактировать».
- Поля заметок растут по мере ввода, есть кнопка «⤢ Развернуть» на весь экран. Черновик не теряется при переключении.
- Синхронизация: режимы «Вручную», «Автоматически», «Раз в день». Значок состояния показывает: не подключено / есть несохранённые / синхронизировано / ожидает сети.
- Конфликт по SHA обнаруживается до записи: выгрузка прерывается и требует подтверждения перезаписи.

## v17 — календарь и связи между записями

**Сетка времени.** Режимы «День» и «Неделя» показывают настоящую сетку часов: 07:00–21:00 в окне, прокрутка на все 24 часа. События размещаются по времени начала и длительности, пересекающиеся делят ширину колонки, события «на весь день» вынесены в полосу над сеткой. У сегодняшнего дня видна линия текущего времени.

**Месяц.** Названия событий снова видны (правило, скрывавшее их на телефоне, удалено), при переполнении — счётчик «+N». Нажатие на пустое место дня открывает этот день в режиме «День».

**Создание из идеи.** В карточке идеи есть «＋ Создать задачу» и «＋ Создать событие». Связи двусторонние: `idea.taskIds`, `idea.eventId`, `task.ideaId`.

**Переходы между записями.** Заголовки задач, идей и событий кликабельны в любых списках и карточках. Связанная запись открывается поверх текущей, кнопка «‹ Назад» в шапке окна возвращает на предыдущую.

**Модальные окна.** Подложка окна поднята выше боковой панели, исправлено расхождение классов `.modal-header`, учтён верхний safe-area на iPhone.

## v18 — карточка события и стабильность формы

**Событие открывается как карточка, а не как форма.** Нажатие на событие в месяце, в сетке дня/недели, в полосе «Весь день», а также по названию или значку «⌕» в списке под календарём открывает режим чтения: когда, тип, категория, источник, место, повторение, описание, связанные задачи и идеи. Внизу — «＋ Задача», «Дублировать», «Удалить», «Закрыть» и «✎ Редактировать». Форма правки открывается только по «✎», возврат — кнопкой «‹ Назад».

**Правка события открывает именно это событие.** Блок «связанные задачи» больше не дописывается в форму правки: он перестраивал разметку после заполнения полей и обнулял их, поэтому у событий со связями форма выглядела пустой. Связи показываются только в карточке чтения, форма правки содержит поля события и открывается уже заполненной. Заголовок окна правки называет событие.

**Промах по фону исправлен.** Плашки событий в месяце стали кнопками, а обработчик нажатия на событие перенесён в начало цепочки — раньше нажатие проходило к подложке дня и открывало создание новой записи.

**Контент.** Панель «Календарь публикаций» удалена: она дублировала раздел «Календарь». Остался список материалов.

**Вёрстка формы на телефоне.**
- Элементам сетки формы задан `min-width: 0`, телу окна — `overflow-x: hidden`: поля больше не выходят за край экрана.
- Кнопки «＋ / ✗» рядом с выпадающими списками зафиксированы по ширине и не выдавливаются наружу.
- Поле заметки растёт без скачка — позиция прокрутки сохраняется.
- Заголовок окна на телефоне компактнее (20 px), длинные слова и ссылки переносятся.

## Как убедиться, что установлена нужная версия

В правом верхнем углу рядом с датой стоит метка сборки, например `v19`. Если после обновления там старый номер — браузер отдал файл из кэша service worker: обновите страницу ещё раз или закройте и снова откройте приложение с «Домой».
